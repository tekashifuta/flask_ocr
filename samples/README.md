# Sample files used for testing

Six files, all of them **synthetic** (generated by `tools/make_samples.py`, no
personal data, all text fictitious) and all of them accepted by the application as
shipped. They cover the four input paths, the "nothing to read" case and the
structured fields of the review page.

| File | Size | Kind | Pages | How it is read | Result of the run below |
|---|---|---|---|---|---|
| `images/scan_invoice.png` | 23,292 B | image | 1 | OCR | 53 chars, 9 words, 95.11 % confidence |
| `images/scan_invoice_fields.png` | 55,850 B | image | 1 | OCR | 156 chars, **all five structured fields** |
| `images/scan_receipt.jpg` | 27,702 B | image | 1 | OCR | 50 chars, 9 words, 96.00 % confidence |
| `images/blank_page.png` | 2,336 B | image | 1 | OCR | 0 chars, no confidence - the "no text found" page |
| `pdf/scanned_invoice_3_pages.pdf` | 76,897 B | pdf | 3 | OCR, **every** page | 178 chars, 30 words, 95.47 % mean confidence |
| `pdf/digital_report_text_layer.pdf` | 735 B | pdf | 1 | **embedded** text layer - Tesseract is never called | 93 chars, 15 words, no confidence |

What each file is for:

* **`scan_invoice.png`** - the ordinary case: a crisp white page with three lines of
  black text, the shape a flatbed scanner produces. Exercises the image pipeline
  (decode, EXIF rotate, grey/contrast preprocessing, upscale, one Tesseract call).
  Of the structured fields it carries an invoice number (`10042`) and a total
  (`128.50 EUR`); the supplier is only the header line (`ACME`) and there is no
  date - exactly what the review page shows for it.
* **`scan_invoice_fields.png`** - an invoice with **every** field labelled
  (`Supplier:`, `Invoice no:`, `Date:`, `Subtotal:`, `VAT 19%:`, `Total:`). Upload
  this one first to see the review step: five pre-filled fields, each with the
  confidence of the rule that found it, and the extracted text underneath. Its
  1200x500 page is taller than the others on purpose - the default page height
  would clip the `Total` line.
* **`scan_receipt.jpg`** - the same text quality through the **JPEG** code path
  (lossy compression, `.jpg`/`.jpeg` extension handling). A receipt has no labels,
  so the parser guesses the first line as the supplier and the only amount as the
  total - which is what the low-confidence badge on the review page is for.
* **`blank_page.png`** - a white page. The upload must succeed with **empty** text
  and a friendly notice instead of an error, and the record must store zero
  characters (the SHA-256 of "" is `e3b0c442…b855`).
* **`pdf/scanned_invoice_3_pages.pdf`** - an image-only PDF (a scanner output, no
  text layer). Every page has to be rasterised at `OCR_DPI` and OCR'd; the result
  keeps the page markers `----- Page n of 3 -----` and the three page rows land in
  `ocr_extractions_pages`.
* **`pdf/digital_report_text_layer.pdf`** - a born-digital PDF (hand written, 735
  bytes, selectable text). It must be read from its text layer instantly
  (`method = embedded`, `confidence = null`) - if this file is ever OCR'd instead,
  the `MIN_EMBEDDED_TEXT_CHARS` decision is broken. It is also the file that proves
  the field parser does **not** invent a supplier or an invoice number for a
  document that is not an invoice.

## Regenerating them

```powershell
cd d:\Python_Projects\flask_ocr
env\Scripts\python.exe tools\make_samples.py
```

The script writes all six files (same text, same geometry) and prints a manifest:

```
samples\images\scan_invoice.png                 23292  b4f34b9446de39e1     1  ocr
samples\images\scan_invoice_fields.png          55850  06a196fc07375c85     1  ocr
samples\images\scan_receipt.jpg                 27702  814e664f7418b749     1  ocr
samples\images\blank_page.png                    2336  5b4c5395d6aaa066     1  ocr
samples\pdf\scanned_invoice_3_pages.pdf         76897  fd0a380e6346c6d3     3  ocr
samples\pdf\digital_report_text_layer.pdf         735  de3b555f3baf8716     1  embedded
```

No downloads and no fonts to install: a TrueType font from the operating system is
used (Arial on Windows, DejaVu on Linux, …), with Pillow's built-in font as the last
resort. Because of that the **pixel** digests above belong to the Windows/Arial run
- different fonts change the bytes and the confidence values slightly, never the
recognised text. The PNG/JPEG images are byte-for-byte reproducible; the two PDFs
are not, because Pillow's PDF writer stamps a creation date into every file it
writes, so their digests differ from run to run (the text, the page count and the
sizes do not). Nothing is hand-edited, so the files can always be re-created from
the script.


## How they were verified

```powershell
env\Scripts\python.exe tools\verify_samples.py
```

The script builds the real Flask app (only pointed at a throw-away SQLite file),
uploads every sample through the HTTP stack (`POST /api/ocr`) and asserts the kind,
the page count, the extraction method, the expected text, the structured fields the
document must yield and that every upload was stored - checked twice, through
`GET /api/database/records` and with plain `sqlite3`:

```

-----------------------------------------------------------------------------------------------------------

images/scan_receipt.jpg                    200 image      1 ocr           50   96.0    3/5       3  ok
images/blank_page.png                      200 image      1 ocr            0      -    0/5       4  ok

  #1   scan_invoice.png                   image  pages=1 chars=53 fields=(ACME, 10042, 128.5, EUR) sha256=6bda0ca88e80
  #2   scan_invoice_fields.png            image  pages=1 chars=156 fields=(Northwind Trading GmbH, INV-2026-0042, 140.42, EUR) sha256=f64350f1e20c
```

The `fields` column is `found/total` of the five structured fields, and the listing
at the bottom prints what actually landed in the `ocr_extractions` columns - the
values the review page showed, read back with plain SQL.

Exit code `0` means everything passed, `1` a check failed, `2` Tesseract is missing
(the images and the scanned PDF cannot be checked without the engine).

## Using them by hand

1. Start the app (`env\Scripts\python.exe run.py`) and open
   <http://127.0.0.1:5000>.
2. Drag `samples/images/scan_invoice_fields.png` onto the drop zone and press
   **Extract and review**. The review page shows the extracted text and five
   pre-filled fields (supplier, invoice number, date, total, currency), each with the
   confidence of the rule that found it. Correct anything you like and press
   **Save reviewed data** - the values left in the fields are the ones stored.
3. Drop several files at once (for instance `scan_invoice.png` and
   `scan_receipt.jpg`): they are reviewed on one page, and every card has its own
   **Store this document** checkbox.
4. Repeat with the 3-page PDF (three page cards, page markers in the copied text)
   and with the digital PDF (**no** OCR run: `embedded`, instant).

5. Look at the records view (<http://127.0.0.1:5000/database/records>): the
   supplier / number / date / total column shows the reviewed values. Search for
   `invoice` and download the `.xlsx` export.

Without the browser, the same files go through `curl`:

```bash
curl -F "file=@samples/images/scan_invoice.png" http://127.0.0.1:5000/api/ocr
curl -F "file=@samples/images/scan_invoice.png" -F "file=@samples/images/scan_receipt.jpg" \
     http://127.0.0.1:5000/api/ocr/batch
```

The extracted text of the two image samples exactly matches the seed data in
`sql/mysql_schema.sql` and `sql/sqlite_schema.sql`, so a database created from
those scripts holds records for these very files.
