{{ store.label }} storage

Where the extracted text is kept

The extracted text lives in a relational database - a MySQL server, or one local SQLite file - so results survive a restart and can be queried with plain SQL. Either store creates what it needs on connect, and the records view button in the header searches every stored file name and its extracted text. Nothing is contacted until you connect, and a store that is not there never costs you an extraction: the text is still shown, with a warning next to it.

Point the application at any reachable MySQL server. On connect the schema is created for you: {{ form.database }} is created when missing (CREATE DATABASE IF NOT EXISTS) and the tables {{ form.table }} (one row per upload: file name, upload date/time and the extracted content) and {{ form.pages_table }} (one row per page) are created with CREATE TABLE IF NOT EXISTS.

Use a local SQLite file

{% if database.connected and database.provider == 'sqlite' %} Connected {% endif %}

The same two tables, in one file, through the standard library's sqlite3: nothing to install, no credentials, no server. The file, its tables and its indexes are created on connect, exactly like the MySQL schema. This is the store to use for tests and local work, and it is also what DATABASE_BACKEND=auto falls back to at start-up when MySQL is not reachable. Set SQLITE_PATH to make another location the default.

A relative path is resolved from the directory the application runs in, and :memory: keeps everything in RAM (gone when the process exits - handy for a quick check). The tables default to {{ database.backends.sqlite.settings.table }} and {{ database.backends.sqlite.settings.pages_table }}.
